# 설계: 구간별 큰 커널(segment megakernel) — 노드당 메모리 대역폭 85% 를 향해

2026-11-06 저녁, 설계 v0. 바탕 숫자는 이날 측정(RESULTS.md 11-06 절들, `tools/probe/mkprobe.hip`, `fixcost/megakernel-1106/`).
상태: 설계 v0 + **1단계 1a 실측(7절) — 구간 커널만으로는 빨라지지 않음, 계획 수정.** 3–4절의 기대치는 측정값으로 한 계산이고 실측이 아니다.

## 1. 목표와 지금

- 목표: 2노드 TP 디코드(MTP 없음)에서 노드당 가중치 읽기 = 2.83 GB/토큰 × tok/s ≥ 0.85 × 239.7 GB/s(1노드 GPU 읽기 실측) = **204 GB/s ≈ 72 tok/s**.
- 지금(ZC=3 + 앞서기 2): 38.5 tok/s = 109 GB/s = **45%**. 토큰 ≈26 ms.

| 토큰당 몫(none, 노드 하나) | ms | 근거 |
|---|---:|---|
| 가중치를 대역폭대로 읽는 시간(2.83 GB / 239.7 GB/s) | 11.8 | 바닥 |

| 　└ 커널 사이 빈틈 | ≈3.9 | 토큰당 커널 1313개 × 커널 하나 바닥 2.2–4 µs(`kfloor.hip`) |
| 　└ 작은 커널 계산·대역폭에 못 미치는 행렬곱 | ≈4 | hc up/down ≈156 GB/s, MoE down ≈137, GLU ≈174, norm·게이트·top-k 등 수백 개 |

85% 이면 토큰 ≈13.9 ms — 바닥 11.8 ms 위에 2 ms 만 남는다. 커널 묶기를 하나씩 더하는 길(한 번에 1–2%)로는 닿지 않는다.
**DRAM 이 쉬는 시간(빈틈·동기화·AR 기다림·작은 연산)을 없애거나, 그 시간에 다음 가중치를 미리 읽게** 해야 한다.

## 3. 설계

### 3.1 단위: AR 사이 구간 하나 = 커널 하나

메타 백엔드는 이미 그래프를 AR 지점에서 나눠 서버에 부분그래프로 보낸다. 층마다 두 종류:

- **B형(MoE)**: hc_post(앞 AR 결과) → norm → hc down(+inject) → scale·silu → hc up → hc_pre → 라우터(BF16) → top-k softmax
  → 전문가 gate/up GLU(10개) → down → 가중합 → 부분합 내보내기 → AR. 노드당 가중치 ≈22 MB(hc 6.2, 라우터 2.6, GLU 8.7, down 4.6).
- **A형(GDN 36층 / 어텐션 12층)**: shared expert(복제) → 게이트·더하기 → hc_post → norm → hc 섞기 → GDN(qkv+gate 투영, conv, q/k norm,
  beta/alpha·gates, 재귀, gated norm) 또는 어텐션(q·k·v, norm·rope, indexer, top-k, flash attention, 게이트) → 출력 투영 → AR.
  노드당 GDN ≈29.5 MB(shexp 3.4, hc 6.2, qkv+gate 14.4, 출력 5.4), 어텐션 ≈33 MB.

서버의 ggml-cuda 가 부분그래프 전체가 이 틀과 맞는지(연산·모양·형식) 보고, 맞으면 **상주 블록 커널 하나**로 돌린다. 안 맞으면(prefill, 다른 모델,
드문 모양) 지금 경로 그대로. 토큰당 커널 1313 → ≈100(구간 96 + 경계), 커널 사이 빈틈 3.9 → ≈0.3 ms.

### 3.2 커널 안: 단계 + 동기화 + 앞서 읽기

- 협동 실행으로 블록 40–80개(전부 상주 보장). 연산 하나 = **단계**, 의존이 있는 단계 사이에 전역 동기화(0.3–0.7 µs).
  B형 ≈8 단계, A형 GDN ≈12, 어텐션 ≈16 → 구간당 동기화 ≈10 µs 이하.
- 작은 연산(norm, scale·silu, 게이트, 더하기, q8_1 양자화)은 따로 단계를 두지 않고 다음 행렬곱 단계의 앞머리에서 **블록마다 같은 값을 다시 계산**한다
  (지금 `k_hc_up_pre` 가 silu q8 을 블록마다 만드는 방식). 10240 원소 norm 은 L2 에서 1–2 µs.
- **앞서 읽기(핵심)**: 가중치는 활성값에 의존하지 않는다. 각 블록은 다음 단계에 맡을 가중치 행을 동기화·기다림 **전에** 내보낸다(레지스터/LDS, 깊이 2단계).
  1 MiB 단계에서 150 → 175 GB/s(측정). 더 멀리는 **MALL 에 미리 읽기**: 지금 단계가 작아 DRAM 이 남을 때와 AR 을 기다릴 때, 일부 웨이브가 앞으로 올
  dense 가중치(정해진 순서)를 읽어 MALL(≤24 MB 앞까지)에 올려 두면 그 단계는 500–800 GB/s 로 읽힌다(측정). 전문가 가중치는 top-k 뒤에야 정해지므로
  top-k 단계 직후부터 앞서 읽는다.
- **AR 은 커널 안에서**: 마지막 단계가 부분합을 호스트 coherent 버퍼에 쓰고 플래그를 올린다(지금 ZC=3 의 내보내기 커널이 하는 일). 대리 스레드가
  주고받는 동안(≈28 µs) 다음 구간 커널은 이미 대기열에 있고(앞서기 2), 시작하자마자 **자기 첫 단계들의 가중치를 MALL 로 읽으면서** 받기 플래그를 본다.
  28 µs × 240 GB/s ≈ 6.7 MB — 다음 구간의 hc down/up·shared expert(≈9.6 MB)의 대부분. AR 기다림이 쓸모 있는 DRAM 시간이 된다.

### 3.3 값이 그대로여야 한다(지금 규칙 유지)

- 행렬-벡터 곱은 지금 mmvq 와 같이 **워프 하나가 한 행**, 같은 lane 보폭 누적과 같은 워프 합. 어느 블록·워프가 그 행을 맡든 값이 같다.
  4토큰(MTP 검증)도 열마다 같은 순서(지금 T≤4 묶기와 같음).
- 블록 크기에 묶인 축소(예: `rms_norm_f32<1024>` 의 1024 스레드 트리)는 같은 트리를 그대로 — 상주 블록이 1024 스레드면 그대로, 작으면
  한 스레드가 '가상 스레드' 여럿의 부분합을 따로 들고 같은 순서로 합친다.
- GDN 재귀·flash attention tile·indexer·top-k 처럼 블록 모양이 정해진 커널은 같은 모양의 '가상 블록'으로 단계 안에서 돌린다(LDS 를 나눠 씀).
  블록 전체 `__syncthreads` 를 쓰는 커널은 가상 블록 = 실제 블록이 되게 단계의 블록 수를 맞춘다.
- 겹침 규칙: 단계의 출력이 다른 블록이 아직 읽는 입력과 메모리를 같이 쓰면 그 단계는 출력을 다른 버퍼로(또는 동기화 뒤로).
  11-05 의 GDN norm 경쟁과 같은 부류 — 상대 노드 GPU 부하 조건(`repro.sh`)으로 확인.
- 검증 스위치: 구간 커널 결과와 지금 경로 결과를 단계마다 비트 비교(`*_VERIFY` 와 같은 방식), 기준 해시.

## 5. 위험과 모르는 것

- **레지스터 압박**: 커널 하나의 VGPR 은 가장 무거운 단계가 정한다(GDN 재귀·flash attention). 상주 블록 수가 줄면 작은 단계 대역폭이 떨어진다 →
  필요하면 구간을 둘로(무거운 단계만 따로 커널) 나눈다.
- **협동 실행과 다른 GPU 작업**: 상대 노드에서 다른 프로세스가 GPU 를 쓰면 상주가 늦어질 수 있다(협동 실행은 전 블록 상주를 보장하지만 시작이 늦어짐).
  부하 조건 시험 필수. 커널 안에서 무한히 도는 대기는 시간 제한(워치독)을 둔다.
- **MALL 정책**: 미리 읽기가 MALL 에 남는지, 다른 읽기에 밀리는지는 `mkprobe` 처럼 단독으로만 확인했다. 실제 구간에서 다시 잰다.
- **전문가 가중치**: top-k 뒤에야 정해져 앞서 읽기 창이 짧다(GLU 8.7 MB 는 큰 단계라 원래 ≈220 GB/s).
- **유지보수**: 패턴이 맞을 때만 쓰는 경로라 모델 그래프가 바뀌면 조용히 지금 경로로 돌아간다 — 맞음/안 맞음을 로그로 남긴다.
- **컴파일**: 큰 커널의 컴파일 시간·스필. 단계 1 에서 확인.

## 6. 참고(공개 자료)

같은 생각의 공개 구현: 디코드를 상주 커널 하나로 돌리는 "megakernel" 접근(예: Hazy Research 의 Llama megakernel, Mirage persistent kernel).
우리 경우는 (1) 노드 둘의 AR 이 구간 경계에 있고 (2) 값을 비트 그대로 지켜야 하며 (3) APU 의 MALL 을 앞서 읽기 버퍼로 쓸 수 있다는 점이 다르다.

## 7. 1단계 결과(1a, 2026-11-06 22:30)와 바뀐 계획

- 한 것: MoE 구간 앞머리 세 커널(hc down Q6_K → hc up/pre → 라우터 BF16)을 상주 커널 `k_seg_moe_head` 하나로(단계 3, 동기화 2). 값 같음(두 노드 비트 검증, 해시).
- 실측: 상주 커널 56.7 µs vs 세 커널 계산 합 ≈54.5 µs. 디코드는 보통 실행이면 같고(38.26 vs 38.17), 협동 실행이면 −2.5%. MALL 앞서 읽기는 65.1 µs 로 손해.
- 뜻: 3.4 절의 '작은 연산·대역폭 미달 행렬곱 ≈4 → ≈1 ms' 는 틀렸다. 작은 단계는 커널 경계나 DRAM 대역폭이 아니라 **워프 하나가 한 행을 차례로 읽는 지연 사슬**에
  묶여 있다(hc down: 324행뿐이라 워프 324개가 각자 20번 차례로 읽음). 단계를 한 커널에 모으거나 데이터를 MALL 에 올려도 이 사슬은 그대로다.
  협동 실행은 ROCm 에서 비싸서 상주 커널은 보통 실행(블록 수 = 상주 가능 수)으로 낸다.
- 바뀐 계획:
  1. **지연 사슬 줄이기(값 그대로)**: 행 루프를 펼쳐 여러 블록의 읽기를 먼저 내고 더하기는 원래 순서대로(fast-math 없음 → 컴파일러가 순서를 안 바꿈).
     대상 hc down(20회), 어텐션 출력 Q8_0(24회), 라우터, hc up. 커널 시간으로 먼저 확인.
  2. 행이 적은 행렬곱에 워프를 더(행 하나를 여러 워프가 맡으면 더하기 순서가 바뀌므로 안 됨 → 행 안 병렬은 그대로, 한 워프가 행 여럿을 번갈아 읽어 사슬을 겹치기).
  3. 구간 커널은 1·2 로 단계가 대역폭에 가까워진 뒤에 다시 — 그때는 경계(≈3 µs × 96 × 여럿)와 AR 기다림 겹치기 몫이 남는다.
